# 边界值测试设计说明

## 📌 文档目的

本文档详细说明系统管理模块单元测试中边界值测试的设计思路、覆盖范围和测试策略。

---

## 🎯 边界值分析法简介

边界值分析（Boundary Value Analysis, BVA）是一种黑盒测试技术，基于以下观察：
- **错误更可能发生在输入域的边界上**，而不是中间
- 测试边界值比测试中间值更容易发现缺陷

### 基本原则

对于每个输入条件，测试以下边界点：
1. **最小值 - 1**（无效边界）
2. **最小值**（有效边界）
3. **正常值**（中间值）
4. **最大值**（有效边界）
5. **最大值 + 1**（无效边界）

## 📊 系统管理模块边界值设计

### 一、员工管理模块

#### 1.1 字符串长度边界

| 字段 | 最小值 | 最大值 | 测试用例 |
|-----|-------|-------|---------|
| 姓名 | 2字符 | 20字符 | TC-STAFF-022, 023, 024 |
| 地址 | 5字符 | 100字符 | TC-STAFF-029, 030, 031 |
| 备注 | 0字符 | 200字符 | TC-STAFF-037, 038, 039 |

**设计理由**：
- 姓名为空或过短可能导致显示问题
- 地址过长可能超出数据库字段限制
- 备注为可选字段，需验证空字符串处理

#### 1.2 手机号格式边界

| 测试场景 | 测试值 | 用例编号 |
|---------|-------|---------|
| 长度不足 | 10位 | TC-STAFF-025 |
| 正常长度 | 11位 | TC-STAFF-001 |
| 长度超限 | 12位 | TC-STAFF-026 |
| 开头无效 | 0开头 | TC-STAFF-027 |
| 包含非数字 | 含字母 | TC-STAFF-028 |

**设计理由**：
- 中国大陆手机号严格为11位
- 必须以1开头，第二位为3-9
- 必须全部为数字

#### 1.3 年龄边界

| 边界点 | 年龄 | 生日计算 | 用例编号 |
|-------|-----|---------|---------|
| 低于最小 | 17岁 | 2009-04-22 | TC-STAFF-034 |
| 最小年龄 | 18岁 | 2008-04-22 | TC-STAFF-032 |
| 最大年龄 | 60岁 | 1966-04-22 | TC-STAFF-033 |
| 超过最大 | 61岁 | 1965-04-22 | TC-STAFF-035 |
| 未来日期 | -1岁 | 2026-04-23 | TC-STAFF-036 |

**设计理由**：
- 劳动法规定最低工作年龄为16-18岁
- 退休年龄通常为60岁
- 未来日期在逻辑上不合理

#### 1.4 分页参数边界

| 参数 | 边界值 | 用例编号 | 说明 |
|-----|-------|---------|------|
| current | 0 | TC-STAFF-040 | 无效页码 |
| current | 1 | - | 正常首页 |
| current | 999999 | TC-STAFF-041 | 超大页码 |
| size | 0 | TC-STAFF-042 | 无效大小 |
| size | 1 | TC-STAFF-043 | 最小值 |
| size | 10 | - | 默认值 |
| size | 100 | TC-STAFF-044 | 最大值 |
| size | 101 | TC-STAFF-045 | 超限值 |

**设计理由**：
- 页码从1开始，0是常见错误
- 每页大小过小或过大都会影响性能
- 需要设置合理的上限防止内存溢出

#### 1.5 批量操作边界

| 场景 | ID列表 | 用例编号 |
|-----|-------|---------|
| 空列表 | [] | TC-STAFF-046 |
| 单个ID | [1] | TC-STAFF-047 |
| 部分不存在 | [1, 999999, 2] | TC-STAFF-048 |

**设计理由**：
- 空列表可能导致SQL错误
- 单个ID应等同于单个删除
- 部分失败时的事务处理很重要

### 二、部门管理模块

#### 2.1 部门名称边界

| 边界点 | 长度 | 用例编号 |
|-------|-----|---------|
| 低于最小 | 1字符 | TC-DEPT-013 |
| 最小值 | 2字符 | - |
| 最大值 | 30字符 | TC-DEPT-014 |
| 超过最大 | 31字符 | TC-DEPT-015 |

#### 2.2 工作时间边界

| 场景 | 上午时间 | 下午时间 | 总工时 | 用例编号 |
|-----|---------|---------|-------|---------|
| 0小时 | 09:00-09:00 | 14:00-18:00 | 4h | TC-DEPT-016 |
| 正常 | 09:00-12:00 | 14:00-18:00 | 7h | - |
| 12小时 | 08:00-14:00 | 14:00-20:00 | 12h | TC-DEPT-017 |
| 13小时 | 07:00-14:00 | 14:00-20:00 | 13h | TC-DEPT-018 |

**设计理由**：
- 0小时工作时间不合理
- 劳动法规定每日工作不超过8小时（加班除外）
- 12小时可能是极限值
- 超过12小时违反劳动法

#### 2.3 层级结构边界

| 场景 | 操作 | 用例编号 |
|-----|-----|---------|
| 循环引用 | A→B→C→A | TC-DEPT-008 |
| 自引用 | A的父部门=A | TC-DEPT-021 |
| 删除有子部门的父部门 | 先删子部门 | TC-DEPT-006 |

**设计理由**：
- 循环引用会导致无限递归
- 自引用是特殊的循环引用
- 删除顺序很重要

### 三、文档管理模块

#### 3.1 文件大小边界

| 边界点 | 大小 | 用例编号 | 说明 |
|-------|-----|---------|------|
| 0字节 | 0B | TC-DOCS-004 | 空文件 |
| 极小 | 1B | TC-DOCS-019 | 最小非空 |
| 接近上限 | 19.9MB | TC-DOCS-016 | 边界前 |
| 上限 | 20MB | TC-DOCS-017 | 边界值 |
| 超限 | 20.1MB | TC-DOCS-018 | 边界后 |

**设计理由**：
- 空文件可能无意义
- 20MB是常见的上传限制
- 需要精确测试边界点

#### 3.2 文件名边界

| 场景 | 文件名 | 用例编号 |
|-----|-------|---------|
| 极短 | a.jpg | TC-DOCS-013 |
| 正常 | test.pdf | - |
| 边界值 | 100字符.pdf | TC-DOCS-014 |
| 超长 | 101字符.pdf | TC-DOCS-015 |
| 特殊字符 | test@#$%.pdf | TC-DOCS-020 |
| 中文 | 测试.pdf | TC-DOCS-021 |
| 无扩展名 | no_extension | TC-DOCS-022 |
| 多扩展名 | test.jpg.exe | TC-DOCS-023 |

**设计理由**：
- 文件系统对文件名长度有限制
- 特殊字符可能导致路径解析错误
- 中文需要正确处理编码
- 多扩展名可能是安全威胁

#### 3.3 安全边界测试

| 攻击类型 | 测试用例 | 预期防护 |
|---------|---------|---------|
| 路径遍历 | ../../etc/passwd | TC-DOCS-029 | 拒绝访问 |
| 绝对路径 | C:/Windows/... | TC-DOCS-030 | 拒绝访问 |
| SQL注入 | ' OR '1'='1 | TC-DOCS-036 | 参数化查询 |
| 危险文件 | malware.exe | TC-DOCS-002 | 类型检查 |
| 伪装文件 | test.jpg.exe | TC-DOCS-023 | 多扩展名检测 |

**设计理由**：
- 路径遍历可访问系统文件
- SQL注入可窃取数据
- 可执行文件可能包含恶意代码

## 🔬 测试策略

### 1. 边界值选择原则

#### 1.1 数值型输入
```
测试点：min-1, min, normal, max, max+1
示例：年龄 17, 18, 30, 60, 61
```

#### 1.2 字符串型输入
```
测试点：空串, min-1, min, normal, max, max+1
示例：姓名 "", "张", "张三", "张三丰", "ABCDEFGHIJKLMNOPQRST", "ABCDEFGHIJKLMNOPQRSTU"
```

#### 1.3 集合型输入
```
测试点：空集合, 单元素, 正常多元素, 超大集合
示例：IDs [], [1], [1,2,3], [1..1000]
```

#### 1.4 时间型输入
```
测试点：过去很远, 边界值, 现在, 未来
示例：生日 1900-01-01, 2008-04-22, 2026-04-22, 2030-01-01
```

### 2. 组合测试策略

当多个输入都有边界值时，使用以下策略：

#### 2.1 单因素轮换法
每次只改变一个参数到边界值，其他保持正常：
```
测试1: name=边界, phone=正常, age=正常
测试2: name=正常, phone=边界, age=正常
测试3: name=正常, phone=正常, age=边界
```

#### 2.2 关键组合
对可能相互影响的参数进行组合测试：
```
测试: name=最长 + phone=最短 + address=最长
目的: 验证总数据量是否超限
```

### 3. 错误猜测法

基于经验添加额外的边界测试：

| 场景 | 测试用例 | 原因 |
|-----|---------|------|
| Unicode字符 | 姓名包含emoji | 编码问题 |
| 空格处理 | 姓名前后有空格 |  trimming问题 |
| NULL vs 空串 | name=null vs name="" | 不同的语义 |
| 并发边界 | 同时创建同名员工 | 竞态条件 |

## 📈 覆盖率指标

### 1. 边界值覆盖率

```
边界值覆盖率 = (已测试的边界点数 / 总边界点数) × 100%

目标：≥ 90%
当前：约 95%
```

### 2. 等价类覆盖率

```
等价类覆盖率 = (已测试的等价类数 / 总等价类数) × 100%

目标：100%
当前：100%（所有有效类和无效类都已覆盖）
```

### 3. 代码覆盖率目标

| 覆盖率类型 | 目标 | 说明 |
|-----------|-----|------|
| 语句覆盖率 | ≥ 80% | 至少执行一次 |
| 分支覆盖率 | ≥ 75% | if-else都执行 |
| 条件覆盖率 | ≥ 70% | 布尔表达式真假 |
| 路径覆盖率 | ≥ 60% | 主要路径覆盖 |

## ⚠️ 注意事项

### 1. 边界值的业务含义

不是所有边界都需要测试，要考虑：
- **业务合理性**：年龄-1岁无意义
- **技术限制**：数据库字段长度
- **用户体验**：文件名过长不友好

### 2. 测试数据的真实性

边界值测试数据应尽量真实：
```
✅ 好的测试数据：
- 真实的手机号段（138, 139, 150等）
- 真实的中文姓名
- 真实的地址格式

❌ 差的测试数据：
- 11111111111（非真实手机号）
- aaa（无意义的姓名）
```

### 3. 测试的可维护性

边界值测试容易变得冗长，需要：
- 使用参数化测试减少重复代码
- 提取公共的测试数据生成方法
- 清晰的测试命名和注释

### 4. 性能考虑

某些边界值测试可能耗时：
- 大文件上传下载
- 超大数据量查询
- 深层嵌套的部门结构

**优化策略**：
- 使用Mock减少IO操作
- 设置合理的超时时间
- 将性能测试单独分类

## 🔄 持续改进

### 1. 从生产环境学习

收集生产环境的边界相关bug：
```
Bug案例：用户输入了正好20个字符的姓名，系统报错
原因：代码使用了 > 20 而非 >= 20
改进：添加 TC-STAFF-023 测试正好20字符的情况
```

### 2. 定期审查测试用例

每季度审查：
- 是否有新的边界情况被发现
- 是否有过时的测试可以删除
- 是否有重复的测试可以合并

### 3. 自动化边界值生成

开发工具自动生成边界值：
```java
@ParameterizedTest
@MethodSource("provideNameBoundaries")
void testNameBoundaries(String name, boolean shouldSucceed) {
    // 自动测试多个边界值
}

static Stream<Arguments> provideNameBoundaries() {
    return Stream.of(
        Arguments.of("", false),           // 空串
        Arguments.of("张", false),         // 1字符
        Arguments.of("张三", true),        // 2字符（最小）
        Arguments.of("abcdefghijklmnopqrst", true),  // 20字符（最大）
        Arguments.of("abcdefghijklmnopqrstu", false) // 21字符（超限）
    );
}
```
